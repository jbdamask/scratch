# Checkpoint: 2026-02-22

## Status: IN_PROGRESS

## Current Task
Debugging browser access to https://nowigetit.us — curl works from terminal but browsers (Chrome, Safari) cannot reach the site.

## Why (Context)
This session completed three infrastructure changes:
1. Migrated HTML publishing from GitHub Gist to S3 (s3_publisher.py replaces gist_publisher.py)
2. Added custom domain nowigetit.us via CloudFront + ACM + Route 53
3. Moved generated HTML from ShareIt bucket to frontend bucket so URLs are https://nowigetit.us/pages/{job_id}.html

All AWS infrastructure is deployed and working. DNS is fully propagated (confirmed via dig against authoritative NS, Google 8.8.8.8, and Cloudflare 1.1.1.1). curl from terminal gets HTTP 200 from both the CloudFront domain and https://nowigetit.us. However, browsers show ERR_CONNECTION_TIMED_OUT (Chrome) and "address is invalid" (Safari).

## Decisions Made
- CloudFront uses S3 website endpoint as custom HTTP origin (no OAC, no bucket config changes)
- ACM cert provisioned in deploy.sh (not CloudFormation) to avoid stack blocking on DNS validation
- www redirect via CloudFront Function (301 redirect, no extra S3 bucket)
- Generated HTML uploads to frontend bucket under pages/ prefix (not ShareIt bucket)
- PUBLISH_BUCKET and PUBLISH_URL env vars control where HTML goes (frontend bucket in Lambda, defaults to ShareIt for local dev)

## Blockers
Browser cannot reach nowigetit.us despite DNS resolving correctly and curl working. Two hypotheses:
1. Browser defaulting to http:// (port 80) instead of https:// (port 443) — most likely
2. Local proxy/VPN/firewall blocking browser traffic — less likely since curl works
