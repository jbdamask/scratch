# Session: Daily Rate Limit + API Cost Tracking

## Status: COMPLETED

## Current Task
Implemented daily processing rate limit and per-job Anthropic API cost tracking for NowIGetIt.

## Why (Context)
The app had no limit on daily PDF processing, risking runaway costs. Each job costs real money (Claude Opus 4.6 API + GitHub API). Also needed visibility into per-job costs.

## Decisions Made
- **SSM Parameter Store for rate limit** (not CloudFormation parameter or DynamoDB counter): Admin can change the limit at any time without redeploying. Value at /nowigetit/daily-processing-limit (default: 20).
- **Scan-based job counting** (not atomic DynamoDB counter): Count actual job records by created_date field instead of maintaining a separate counter. Cleaner data model, no phantom RATE_LIMIT# items in the jobs table.
- **Cost stored as strings in DynamoDB**: Avoids Decimal precision issues. Fields: input_tokens (int), input_tokens_cost (str), output_tokens (int), output_tokens_cost (str), total_cost (str).
- **Claude Opus 4.6 pricing**: Input $5/MTok, Output $25/MTok. SDK doesn't provide cost — must calculate manually.
